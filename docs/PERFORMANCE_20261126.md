# 4K 预览与模式切换优化

日期：2026-11-26。版本：1.1.9.2611B。本轮在当前电脑测试，Win7 实机验收留后续。

## 壁纸淡入淡出的调用链

正式程序经 `SWP_SetWallpaper` 调用 `SystemParametersInfoW(SPI_SETDESKWALLPAPER, ..., SPIF_UPDATEINIFILE | SPIF_SENDCHANGE)`，设置一张当前壁纸。程序自己的后端计时器决定下一张图片，再调用同一接口，没有调用 `IDesktopWallpaper` 的系统幻灯片接口。

因此观察到的桌面淡入淡出属于当前 Windows 桌面的呈现行为，程序没有专门实现这段桌面动画，也不保证所有系统配置下都出现相同过渡。导出 `.themepack` / `.deskthemepack` 是独立链路；主题包内的幻灯片参数不参与软件运行中的轮播。

## 找到的开销与修改

1. 旧 `gallery.dll` 在查询图片长度时也会读取、解包图片。原来一次获取先查询长度再读内容，形成两次工作。现在先给 4 MiB 缓冲区读取，只有容量不足才按返回长度重试，最大 64 MiB；已用实际 4,211,824 字节图片校验重试后逐字节一致。
2. 后端加入最多 6 项、16 MiB 的压缩图 LRU 缓存，键包含图库目录、日期、尺寸。导入、删除、迁移成功后清缓存，避免拿到旧图。图库接口仍只在专用线程串行调用。
3. 4K 的主界面、图库与大图查看器优先读取图库已有的 1920×1080 图。浏览选中项只读取预览，应用和导出时独立读取所选原尺寸。缺少 1080p 图时保留原图回退，渲染阶段仍限制预览像素范围。
4. 主图字节未变化时不重新解码；图库预览缓存键将 UHD 映射到 1080p，减少同一显示源的重复任务。
5. WIC 按“解码源→缩放→32 位像素转换”处理，壁纸预览上限为 1920×1080，保留比例。Direct2D 位图随图片复用，预览样式切换不再反复上传相同像素；重建渲染目标时清理关联位图。坏图解码失败保留上一张有效图，清空图片时释放资源。
6. 快速连续切换的实测曾出现图片文件替换报 Win32 error 5。现在只对访问拒绝、共享冲突和锁定错误做最多 375 ms 的有限等待重试；持续失败保留旧文件，仍向上报告错误。后端回归覆盖短暂占用解除及持续锁定的状态保护。
7. 修复标签页切换时分组框透明区域残留上一页图片的问题，并用本机 Computer Use 检查。

## 测量方法与最终结果

`tools/preview_benchmark.cpp` 使用真实后端、图库 DLL、WIC 解码与 ReplicaUi 渲染代码，复制同一图库夹具到全新目录。隐藏窗口和私有内存绘图表面不改变真实桌面；不计入物理输入到显示的端到端耗时。

旧版后端与渲染源码来自优化前提交 `53cf9a6`，仅加入测试访问声明；与新版使用相同的构建选项及平台/网络/图库 DLL。性能轮次顺序执行，避免相互并发。系统文件缓存、文件扫描和其他应用负载仍会影响结果，尤其是原图库的首次解包。

| 项目 | 优化前 | 优化后 |
|---|---:|---:|
| 后端初始化（单次） | 3885.048 ms | 265.337 ms |
| 首次进入图库模式（单次） | 5718.938 ms | 863.929 ms |
| 8 个未命中应用图缓存的选图，p50 / p95 | 3847.823 / 5640.662 ms | 59.272 / 63.854 ms |
| 重复同一条记录选图，25 次 p50 / p95 | 3208.194 / 4219.633 ms | 3.639 / 4.203 ms |
| 重复进入图库模式，15 次 p50 / p95 | 6180.425 / 6526.717 ms | 31.653 / 36.737 ms |
| 显示源解码，15 次 p50 / p95 | 111.455 / 115.276 ms | 21.750 / 24.403 ms |
| 预览样式切换重绘，40 次 p50 / p95 | 16.572 / 22.102 ms | 12.343 / 13.758 ms |

以上是最后一轮已完成计时。前一轮新版未命中选图中位数为 110.136 ms，首次进入图库为 1317.505 ms，可见系统负载仍有影响。新版重复选图与模式切换命中应用缓存，不能等同于首次读入新壁纸的耗时。小样本分位数用于本机定位开销，不作为跨设备性能保证。显示源解码的旧版为 UHD，新版为用户要求的 1080p。

三处 16:9 UHD 预览均断言为 1920×1080。单张解码像素缓冲从 33,177,600 字节降为 8,294,400 字节，即从约 31.6 MiB 降为 7.9 MiB；这不是整个进程内存降低 75% 的测量。保存当前壁纸、图库导出 UHD 均逐字节等于原始 UHD。

仍有的开销：首次进入图库需读原尺寸图片，最后两轮约 0.86–1.32 秒；首次 Direct2D 绘图目标建立约 600–646 ms，多个轮次有波动。真实桌面系统 API 调用及过渡动画未纳入隔离性能基准。底层易语言图库格式和 DLL 仍是未缓存读取的重要成本，后续如需继续降低首次延迟，应单独评估兼容读取层和异步预取。

## 回归与证据

- 完整六阶段构建通过，EXE 与四个自建 DLL 的字符串版本均为 `1.1.9.2611B`，数值版本为 `1.1.9.2611`，带预发布标志。
- 后端覆盖配置重开、收藏、图库/收藏轮播、暂停、空/单图库、保存/五尺寸导出、主题、删除、迁移冲突、锁定回滚、网络超时/取消与任务退出。
- 主题专项覆盖两种格式、五尺寸、UHD、Unicode 名称、坏模板后重试及无效 JPEG/名称拒绝。
- 实网测试通过三来源、十五档 JPEG 下载；没有安装主题或更改真实桌面。
- 最终本机界面检查使用 `build/tests/ui-release-20261126`，确认版本标题、4K 图库中从雪山切换海鹦时图片及详情同步、模式页无上一页残影。测试实例已退出；三套界面原型另见 `UI_DESIGN_OPTIONS.md`，正式 UI 尚未整体替换。

本地证据保存在 `build/tests/`（构建与测试产物不提交 Git）：

## 复测

在工程根目录依次运行，性能基准期间不要同时运行其他产品测试：

```bat
build.cmd
tools\run_preview_benchmark.cmd
tools\run_backend_integration_test.cmd
tools\run_theme_integration_test.cmd
```

集成测试与性能基准需要本机隔离夹具 `build/tests/isolated-current-20261121-01/Gallery`。性能脚本也可传入优化前 `src` 目录，对同一夹具测量基线。测试均新建数据目录，不操作系统自启项或旧软件用户数据。
